# SMS UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Templates written and approved through the platform, sent by picking them — in bulk, scheduled, or to one client from the bitim page.

**Architecture:** `sms_templates` becomes the mirror of Eskiz's templates (state synced by amo-sync, which also submits new ones); a new `send_sms_template()` builds texts from an approved template and stores a send time; amo-sync sends only what is due. The web gets one shared send block (`SmsSend`) used on the bitim page, the client card and the SMS page.

**Tech Stack:** Postgres (095), Bun worker, React.

**Spec:** `docs/superpowers/specs/2026-11-11-sms-ux-design.md`

## Global Constraints
- New migration `095_sms_templates_schedule.sql` only; SQL test on a throwaway stand; backup before applying; apply before the frontend merge.
- Eskiz credentials only in amo-sync. bun, strict TS, Uzbek copy, token utilities, `tbl`/`Pager`, `Sheet`.
- The old `send_sms(kind, text, ids)` stays callable (nothing else uses it after this, but no breaking drop).

## Review Focus
1. A blank left empty or a template not approved → refused with a clear Uzbek message, nothing queued. (T2 SQL test)
2. A Sotuv user sending to two clients, or touching template state (status/eskiz_id/kind) through the API → refused. (T2)
3. A send at 22:00 or with a past time → queued, goes at the next 9:00 / now; cancelled before then → never sent. (T2 + T3)
4. Eskiz text with different spacing/newlines than ours → still linked to our row, no duplicate. (T3 test)
5. A template edited after approval → back to moderation, not sendable until approved again. (T2)

## Tasks

### T1 — text helpers (`src/lib/sms.ts`, `src/lib/sms.test.ts`)
`blanks(text): string[]` (the `{…}` keys except `ism`, in order, unique); `fillTemplate(text, values, firstName): string`; `toPattern(text): string` (`{ism}` → `%w`, others → `%w{1,10}`) — the same rule is mirrored in amo-sync. Tests: blanks order/uniqueness, fill with a first name only, pattern conversion.

### T2 — migration 095 + test
`sms_templates`: `status` (draft/moderation/approved/rejected, default draft), `kind`, `eskiz_id` unique, `pattern`, `hidden`, `submitted_at`, `checked_at`; guard trigger: API roles may set status only draft/moderation, never eskiz_id/kind/pattern/checked_at; editing `text` of a non-draft template sends it back to moderation (eskiz_id/kind/pattern/submitted_at cleared). Read policy: + Sotuv bo'limi for approved, not hidden. `sms_campaigns`: `send_at`, `template_id`, `cancelled_at`; `sms_messages.status` + `cancelled`; read policies + Sotuv bo'limi; `sms_messages` into the realtime publication. `send_sms_template(p_template, p_values jsonb, p_client_ids, p_send_at)`: `sms` module, or Sotuv bo'limi with exactly one client; template approved and visible; every blank filled; send_at = greatest(given, now); promo opt-out; returns {campaign_id, queued, skipped}. `cancel_sms_campaign(p_campaign)`: author or `sms` module. `sms_campaign_stats` + send_at, cancelled, template title.

### T3 — worker (`amo-sync/src/sms.ts`, test)
Drain only messages whose campaign `send_at <= now()` and not cancelled. Template sync every 10 min and on `POST /hooks/sms/templates/sync` (session + `sms` or Sotuv bo'limi): submit rows `status='moderation' and submitted_at is null` (`POST user/template`, field `template` = pattern), then read `user/templates` and link/update by eskiz_id, else by squashed pattern, else import (title = first words, `%w…` → `{matn1}`, `{matn2}`…). Pure, tested: `toPattern`, `squash`, `eskizState(status)`, `importText(template)`.

### T4 — data layer (`queries/sms.ts`, `hooks/useSms.ts`, `LiveSync`)
Template CRUD + submit + hide + sync; `sendSmsTemplate`; `cancelSmsCampaign`; `getClientSms(clientId)`; client ids by voronka/bosqich; `sms_messages` → TOUCHES `["sms", "sotuv"]`.
