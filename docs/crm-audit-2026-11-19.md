## 2A. Meta Conversions API

**Xulosa: kod tayyor, lekin prod'da o'chiq. Meta'ga hali birorta event ketmagan.**

### Eventlar

`093_lead_quality_capi.sql` triggerlari → `meta_events_log` (navbat + log) → `amo-sync/src/capi.ts` (har 30 s):

| Event | Qachon navbatga tushadi | Trigger |
|---|---|---|
| `Lead` | Bitim `qualified = true` bo'lganda. `event_id` formaniki, brauzer pikseli bilan deduplikatsiya uchun | `meta_on_lead` |
| `QualifiedLead` | Qo'ng'iroq tahlili `outcome`'i yozildi / qayta qo'ng'iroq / o'ylab ko'radi bo'lsa (rad etdi / maqsadsiz emas) | `meta_on_call_analysis` |
| `Purchase` | Bitim yutilganda (qiymat = Summa yoki ishtirokchi narxi) yoki voronka tadbiriga to'lov tushganda (`value`, `UZS`) | `meta_on_lead`, `meta_on_payment` |

- Bitim + event bo'yicha bir marta (`UNIQUE (lead_id, event_name)`).
- Qayta urinish 1 / 10 / 60 daqiqada, keyin `failed`; 7 kundan eski event `skipped`.
- Endpoint: `graph.facebook.com/v26.0/<pixel>/events`.
- Faqat `capi` maydoni bor bitimlar uchun ishlaydi (`queue_meta_event` aks holda chiqib ketadi).

### Identifikatorlar

- **Yuboriladi:** `ph` va `fn` (SHA-256), `external_id` = SHA-256(bitim id), `fbc`, `fbp`, `client_ip_address`, `client_user_agent`, `event_id`, `event_source_url`, `content_name`.
- **Yuborilmaydi:** email (`em`), Meta'ning `lead_id`'si (leadgen id), alohida `fbclid`.

### Sayt formasi

- `fbc`, `fbp`, `event_id`, sahifa URL'i, IP, User-Agent `crm_leads.capi`'da saqlanadi: 23 ta bitimda, hammasida to'liq (`fbp` 23, `fbc` 23, `event_id` 23, `event_source_url` 23, `client_ip` 23, `user_agent` 23; `site_score` / `site_qualified` 8 tadan).
- `fbclid` kaliti qo'llab-quvvatlanadi (`attribution.ts:13`), lekin DB'da 0 ta.
- Saytning o'zi bu repoda emas, u yerda cookie qanday olinishini tekshira olmadim.

### Instant Form qamrovi: yo'q

Make.com → `/hooks/fb-lead` lidlari `capi`siz ochiladi (`intake.ts:183`), `queue_meta_event` esa `capi` bo'lmasa chiqib ketadi. Natija: 104 ta FB lid va 82 ta sifatli lid CAPI'dan tashqarida. Faqat sayt formasi orqali kelgan bitimlar qamralgan.

### Haqiqiy holat

- Konteynerda `META_CAPI_TOKEN` env'i yo'q. Start logi: `[capi] META_CAPI_TOKEN yo'q — Meta'ga yuborish o'chiq (hodisalar navbatda kutadi)`.
- `meta_events_log`: 7 `Lead` + 5 `QualifiedLead`, hammasi `pending`, `attempts = 0`, `sent_at` bo'sh. Birinchisi 2026-11-11 da, oxirgisi 2026-11-17 da navbatga tushgan.
- Oxirgi muvaffaqiyatli yuborilgan event: **yo'q**. Javob kodlari va xato logi: **yo'q** (hech qachon urinilmagan).
- `Purchase` navbatga umuman tushmagan: yutilgan 18 bitimning birortasida `capi` yo'q.
- 12 tadan 3 tasi allaqachon 7 kundan eski, token qo'yilganda `skipped` bo'ladi.

### Pixel ID va token qayerda

- Pixel ID `amo-sync/src/capi.ts:13`'da hard-code qilingan.
- Token `META_CAPI_TOKEN` env'idan o'qiladi (CLAUDE.md bo'yicha Doppler `fy-system`), faqat so'rov tanasida ketadi, URL'ga, logga yoki saqlangan javobga yozilmaydi.
- `META_TEST_EVENT_CODE` ixtiyoriy (test rejimi).

### Kamchiliklar

1. Token prod'da yo'q, tizim ishlamayapti.
2. Instant Form lidlari qamralmagan. Ular uchun Meta'ning "Conversion Leads" sxemasi kerak: `lead_id` = leadgen id, `action_source: system_generated`.
3. Hamma event `action_source: "website"` bilan ketadi, shu jumladan qo'ng'iroqdan keyingi `QualifiedLead` va oflayn `Purchase`.
4. `em` yuborilmaydi (bazada email bor mijoz atigi 4 ta).
5. `QualifiedLead` AI'ning erkin matnli `outcome`'iga regex bilan bog'langan. "boshqa: og'zaki rozi bo'ldi" kabi javoblar tushib qoladi; sotuvchi bosqichni qo'lda o'tkazishi event bermaydi.
6. Events Manager'da qaysi event optimizatsiya uchun tanlangani kodda ko'rinmaydi.
7. Xatolik haqida ogohlantirish yo'q: `failed` yoki uzoq `pending` eventlar hech kimga xabar bermaydi.

## 2B. AI qo'ng'iroq tahlili

**Xulosa: ishlayapti, avtomatik, natija strukturali.**

### Zanjir

`amo-sync/src/callAnalysis.ts`, har daqiqada 1 ta qo'ng'iroq:

1. `pbx.ts` OnlinePBX tarixini har daqiqada `crm_calls`'ga yozadi.
2. `call_analysis_claim()` javob berilgan (`talk_time > 0`) qo'ng'iroqni oladi (10 daqiqalik "ijara" bilan), mp3 `audioLink` orqali yuklanadi.
3. **STT:** alohida servis emas, Gemini `gemini-3.5-flash-lite` audio'ni A/B ovozli matnga aylantiradi (`transcriptPrompt`). Tillar: o'zbek (lotin) va rus (kirill). Amalda: 192 `uz`, 10 `aralash`, qolgani aralash variantlar.
4. **Tahlil (LLM):** Claude `claude-opus-5-5` (206 tadan 205 tasi), Claude ishlamasa Gemini. Prompt `analysisPrompt()` — "tajribali sotuv bo'limi rahbari va murabbiy" roli, avval qaysi ovoz sotuvchi ekani aniqlanadi, keyin faqat sotuvchi gaplari baholanadi. Ismlar transkripsiya so'roviga, narx va sanalar faqat tahlil so'roviga beriladi.
5. Natija `crm_call_analyses`'ga yoziladi (qo'ng'iroqqa bitta qator).

### Aynan nimalar chiqariladi

- Transkript (vaqt belgisi, sotuvchi/mijoz rollari bilan).
- Xulosa (`summary`, 2–3 gap).
- Natija (`outcome`: yozildi / o'ylab ko'radi / rad etdi / qayta qo'ng'iroq / boshqa).
- Umumiy ball 0–100 (juda qisqa suhbatda `null`).
- 6 mezon bo'yicha scorecard (0–10): salomlashish va tanishtirish; ehtiyojni aniqlash; taklifni foyda orqali tushuntirish; e'tirozlarga javob; keyingi qadamni kelishish; nutq madaniyati.
- Yaxshi tomonlar (`good`).
- Xatolar (`mistakes`): sitata, sabab, "o'rniga ayting", 9 ta qat'iy tegdan biri (`tanishtirmadi`, `ehtiyoj_soramadi`, `foyda_aytmadi`, `etirozga_javob_yoq`, `keyingi_qadam`, `sovutadigan_gap`, `ortiqcha_soz`, `tinglamadi`, `boshqa`).
- Ortiqcha so'zlar soni (`words`).
- Tavsiyalar (`advice`, 2–4 ta).
- Skriptdan tushib qolgan qadamlar (`script_missed`).
- Til (`language`), ishlatilgan model (`model`).

**Chiqarilmaydi:** mijoz uchun keyingi qadam, e'tirozlar ro'yxati, rad sababi, sentiment / ohang, gapirish nisbati, savollar soni, eng uzun monolog, raqobatchilar.

### `outcome` taqsimoti (206 ta `done`)

qayta qo'ng'iroq 55, o'ylab ko'radi 47, boshqa 36, rad etdi 35, yozildi 17, qolganlari erkin matnli variantlar.

### Natija qayerga tushadi

- Qo'ng'iroq qatoridagi ball belgisi va tahlil oynasi (`components/sotuv/CallAnalysis.tsx`) — Qo'ng'iroqlar sahifasi va bitim lentasida.
- Qo'ng'iroqlar → Tahlil tabi (`CallStats.tsx`, `call_analysis_stats()`): sotuvchi bo'yicha tahlil qilingan qo'ng'iroqlar, o'rtacha ball, haftalik trend, top-3 xato tegi.
- Claude connector (`call_analysis_stats`, `call_analyses`, `call_analysis` tool'lari).
- **Bitim maydonlariga hech narsa yozilmaydi.** `outcome` faqat Meta `QualifiedLead` triggerini ishga tushiradi.
- Asosiy Dashboard'da tahlil ko'rsatkichlari yo'q.

### Avtomatik yoki qo'lda

To'liq avtomatik. 2026-11-10 dan beri javob berilgan 211 qo'ng'iroqning hammasi navbatga tushgan, 206 tasi bajarilgan, 5 tasi `failed`. Kunlik: 11-noyabr 41, 12 — 20, 13 — 28, 14 — 24, 16 — 31, 17 — 29, 18 — 30. Qo'lda faqat admin uchun "Qayta tahlil" (`requeue_call_analysis`).

### Kamchiliklar

1. Sotuv skripti bo'sh (`sales_script.body` 0 belgi), shu sabab `script_missed` 206 tahlilning hammasida bo'sh. Skriptga muvofiqlik amalda ishlamayapti.
2. 5 ta `failed`: 3 tasi Gemini bepul tarifining 503 xatosi ("high demand"), 2 tasi "transcript bo'sh". Ogohlantirish yo'q.
3. `call_analysis_claim()` faqat oxirgi 24 soatdagi qo'ng'iroqlarni oladi. Worker bir kundan ortiq to'xtasa, o'sha qo'ng'iroqlar hech qachon tahlil qilinmaydi.
4. Kuniga 150 urinish cheklovi (`CALL_ANALYSIS_DAILY_MAX`); Gemini kaliti task bot bilan umumiy.
5. Mono yozuv: ovozlar kanal bo'yicha ajratilmaydi, rolni model aniqlaydi (UI'da "AI tahlili — xato bo'lishi mumkin" deb yozilgan).
6. Tarixiy 1 339 qo'ng'iroq tahlilsiz.
7. 18 MB dan katta yozuv o'tkazib yuboriladi (`skipped`).
